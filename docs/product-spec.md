# 产品功能地图与业务规则 v0.1

> 定位：私有云 · 整套交付 · 单租户。用途：内部评审对齐，后端按此实现。
> 状态标记：✅ 已闭环（可增删改且落盘） / ◐ 半成品（有界面无逻辑） / ○ 未做 / ✕ 已砍

## 一、产品边界

**做什么**：给企业一套开箱可用的云原生应用平台，业务团队不用懂 K8s 就能交付应用；平台自带底座，客户不感知底层集群。

**部署形态**：单环境，只部署生产。预发与测试环境不设独立环境，验证由「灰度 10% + 自动化回归 + 审批」承担。

**不做什么**（已确认砍掉）：企业空间与多租户隔离、项目配额与审批、成本分摊与计费、应用商店与模板市场、跨集群纳管与多区域调度。

**四条故事线**（评审要都能讲通）

| 故事线 | 一句话 | 支撑页面 |
|---|---|---|
| 三层模型 | 应用 → 组件 → 工作负载，分别对应业务、构建、调度三种边界 | 应用详情、组件拓扑、工作负载 |
| 模块解耦 | Mesh / 云边端可关，关了 UI 收缩但基础功能不塌 | 模块管理、应用详情、工作负载 |
| 配置治理 | 配置集中维护、密钥不落明文、改前知影响 | 配置与密钥、配置与存储 |
| 发布链路 | 组件 → 流水线 → 制品 → 灰度 → 回滚 | 流水线、发布记录、访问入口 |

## 三、核心业务流程

### 流程 1：应用上线

```
新建应用（向导）→ 添加组件（绑定镜像与版本）→ 创建工作负载（副本/资源/调度位置）
   → 绑定流水线 → 运行流水线（构建→推镜像→灰度 10%→回归→审批→全量）
   → 生成发布单 → 审批 → 灰度（按 Mesh 权重）→ 全量 → 记录版本
```

关键节点：审批在生产阶段前；灰度依赖 Mesh，Mesh 关闭时退回原生滚动更新。

### 流程 2：配置变更

```
新增/修改配置（作用域：全部组件 或 指定组件）
   → 选择注入方式（环境变量 / 文件挂载）
   → 【待定】是否走发布单
   → 生效：环境变量需重建 Pod；文件挂载可热更新
```

### 流程 3：故障处置

```
告警产生 → 认领（责任到人）→ 定位（跳转工作负载：日志/事件/指标/链路）
   → 处置（重启/扩容/回滚/改配置）→ 关闭（需填原因）
```

## 四、业务规则

### 4.1 状态机

**应用**

```
运行中 ⇄ 已停止
   ↘ 异常 ↗
```

- 「已停止」= 全部工作负载副本为 0
- 「异常」= 存在就绪率低于阈值的运行中工作负载
- 状态由工作负载聚合推导，**不手工设置**（当前实现是硬编码数字，见第六节）

**组件**

无独立运行时状态，健康度 = 其下工作负载就绪率加权。

**工作负载**

```
待调度 → 运行中 ⇄ 已停止
   ↘ 异常（CrashLoop / 就绪探针失败）
定时任务：待执行 → 运行中 → 已完成 / 失败
```

**发布单**

```
待审批 → 待执行 → 发布中 → 成功
                      ↘ 失败 → 已回滚
```

**告警**

```
未处理 → 处理中 → 已关闭
   ├→ 已忽略（需填原因，永久）
   └→ 静默（需填时长，到时自动恢复未处理）
```

## 六、已修复的实现偏差（2026-10-30）

原文本节列出四处「实现与规则打架」的地方，现已全部修正：

| 原问题 | 修正方式 |
|---|---|
| R-02：组件版本可手改，绕过发布 | 「镜像版本」改为只读字段，提示「由发布流程写入，不在此处修改」；保存逻辑不再接收该字段 |
| 健康度硬编码 | 改为 `appHealth()` 由工作负载推导：Σ就绪实例 / Σ期望实例；无期望实例时显示「—」 |
| 应用状态靠手填 | 改为 `appStatus()` 推导：无负载=待部署、全部副本为 0=已停止、就绪不足=异常、其余=运行中 |
| 停用只是改标志位 | 「停用应用」现在真的把副本置零并记住原值，启用时恢复；不再只改 status 字段 |
| R-05：删 P0 应用过松 | 存在运行中负载时拦截，并列出前三个负载名；需勾选「我知道这会中断线上流量」才能继续 |
| 告警认领是假操作 | 改为真实状态流转：未处理 → 处理中（记录负责人与时间）→ 已关闭；旁路「已忽略」；状态写入快照 |
| 告警统计写死 | 四个统计卡改为实时计算，筛选按钮可用 |

顺带清掉了 6 个「点了没反应」的按钮（告警规则、通知渠道、证书管理、扫描策略、批量固件升级、拉取指令），统一改为置灰 + 悬浮说明「尚未开放」。

## 七、已确认的业务决策（2026-10-30）

以下三项已拍板，写入规则表对应 R-15 ~ R-17。

**Q1｜生产发布强制审批：确认采纳**
P0 应用需应用负责人 + 运维值班两人审批，P1/P2 单人即可。
理由：私有云客户多为内部系统，P0 停机代价远高于审批摩擦。

**Q2｜配置变更走发布单：确认采纳**
配置变更生成独立发布单，带快照、可回滚。
理由：配置错误是线上事故高频原因，而当前回滚只覆盖镜像版本，配置改错了退不回去。**规则已定，实现待做**。

**Q3｜告警分级与响应时限：确认采纳**
严重 5 分钟响应、超时升级到负责人；警告 30 分钟；提示次日处理。
理由：没有时限的分级只是标签。**规则已定，计时与升级链路待做**。
