# PaaS-Prototype-WorkBuddy

云原生 PaaS 平台的高保真交互原型。纯静态实现（HTML + CSS + JS），无构建、无外部依赖，浏览器直接打开即可体验。

## 业务模型

三层结构：**应用 → 组件 → 工作负载**，分别对应业务交付边界、构建发布边界、调度运行边界。

三层各自都有跨应用的全局视图，不必先进入某个应用才能找到下一层：

| 层 | 入口 | 汇总口径 |
|---|---|---|
| 应用 | 应用管理 → 应用列表 | 卡片：组件数、工作负载数、健康度、对外入口 |
| 组件 | 应用管理 → 组件 | 表格：所属应用、角色、运行时、版本、工作负载数、实例就绪/期望、异常 |
| 工作负载 | 应用管理 → 工作负载 | 表格：调度位置（云端 / 边缘 / 端侧）、副本、CPU、重启数 |

组件行点击后落到对应应用的「组件与工作负载」页签并选中该组件，继续加工作负载。

**组件的字段**分四组，都可以在应用详情里点「配置」修改：

| 分组 | 字段 | 说明 |
|---|---|---|
| 身份 | 名称、角色、负责人 | 负责人默认继承应用 |
| 代码与构建 | 代码仓库、分支、构建方式、镜像版本 | 新建流水线时自动带出仓库与分支 |
| 服务契约 | 服务名、协议、端口、存活/就绪探针路径 | 服务名默认等于组件名；详情页与 YAML 同源 |
| 默认规格 | 副本数、CPU、内存 | 新建工作负载时按此预填 |

## 模块化设计

Service Mesh 与云边端协同为可插拔模块，可独立开关。关闭时相关 UI 整体收缩（页签锁定、表格整列移除），而非留空占位，基础功能不受影响。

模块管理页每个模块都有**配置**与**文档**：配置项（控制面地址、注入策略、mTLS、离线自治时长、分发窗口等）按模块区分并持久化；文档给出架构说明、常用命令与排障建议。

## 创建闭环

三层模型不是静态展示，可以完整走一遍「创建 → 变更 → 回收」：

- **新建应用**：概览 / 应用列表右上角，三步向导（基本信息 → 首个组件 → 首个工作负载 → 确认），可只建应用、不建组件，空态会引导继续创建。
- **新建组件 / 工作负载**：应用详情「组件与工作负载」页，资源树标题栏的 `+` 建组件，组件卡片头 `+ 工作负载` 建负载；调度位置随「云边端协同」模块开关收敛，Mesh 字段随 Service Mesh 开关变化。
- **运行时不做手填**：创建组件只选构建方式（Dockerfile / Buildpack 自动识别 / 引用已有镜像），运行时等构建产物出来由「编译构建」阶段回填（取流水线的构建环境），避免表单里的值与真实镜像对不上。
- **扩缩容**：应用详情右上「扩缩容」，一次调整该应用下所有可扩缩负载的副本数，写回表格与事件流。
- **删除**：应用（`···` → 删除应用，需输入名称确认，级联组件/负载/访问入口）、组件、工作负载均有二次确认。
- **数据持久化**：以上写操作落到 `localStorage`（`paas.prototype.db.v1`），刷新后保留；「设计说明」页底部可一键**重置演示数据**。

## 工作负载运行时

工作负载列表或应用详情里点任意工作负载，进入 `#/workloads/<应用>/<组件>/<负载>`，回答「建出来之后跑得怎么样」：

- **概览**：实例数、重启次数、CPU / 内存水位；Pod 列表带 hash 后缀、就绪、重启数、调度节点、IP、Age；容器与探针配置、最近事件。
- **指标**：CPU、内存、P99 延迟、请求速率四条时序曲线，支持 15 分钟 / 1 小时 / 6 小时切换，悬停显示该时刻读数与相对时间。
- **日志**：深色日志流按级别着色，容器切换、级别筛选、关键字高亮、暂停/继续跟随；日志持续追加，暂停时仍在接收。
- **事件**：Normal / Warning 聚合计数，包含调度、拉镜像、探针失败、Sidecar 注入。
- **YAML**：「与运行态对比」生成 unidiff，标出线上多出的副本、hotfix 镜像与调试环境变量；Deployment / StatefulSet / CronJob / EdgeApp 分别生成对应形态。
- **终端**：模拟容器 shell，支持 `ls`、`env`、`ps`、`curl localhost:8080/healthz`、`cat /etc/os-release`、`help`、`clear`。

运行时数据由工作负载字段确定性生成（种子取自负载名），因此新建的工作负载也有自洽的 Pod、指标、日志与 YAML；`Mi` / `Gi` 单位会被归一化后展示。

## 发布闭环

从代码提交到环境上线是一条能走完的链路，不是静态列表：

- **新建流水线**：四步向导（归属与代码 → 构建配置 → 发布策略 → 确认）。归属组件按应用分组；可选开启单元测试、自动化回归、人工审批；创建后立即触发首次运行。
- **运行模拟**：新运行会按阶段推进（约 10 秒走完），日志逐段追加；「重新运行」也会实时推进，无需刷新。
- **运行详情**：`#/cicd/<流水线>/<运行号>`，点构建历史任意一行即可查看该次运行——阶段状态（done / run / fail / 跳过）、提交与制品、质量门禁都随之切换；点阶段卡片或筛选条可按阶段只看该段日志。
- **审批与灰度**：流水线停在「人工审批」时，页头出现「通过审批 / 驳回」；通过后进入灰度 10%，横幅显示观察窗口与错误率，再点「推进灰度」把权重推到 100%，同时写入发布记录与应用事件流。
- **发起发布**：应用详情右上「发布」与组件卡片「发布」打开同一面板——组件 / 环境 / 版本 / 策略 / 是否需要审批 / 变更说明，并预告影响的工作负载与实例数。关闭审批则直接完成，开启则进入待审批。
- **发布记录与回滚**：应用详情「发布记录」页签汇总每次变更（版本、上一版、环境、策略、发起人、审批人、状态），待审批可直接审批，已发布可一键回滚到上一版并恢复组件版本。
- **配置快照与版本历史**：每次发布都会记录当时的配置快照；点组件卡片上的版本 chip 打开「版本历史」，逐版显示配置变更数（`+新增 ~修改 -删除`）。

## 配置、密钥与存储

### 三层归属

| 对象 | 归属 | 谁维护 | 怎么生效 |
|---|---|---|---|
| 配置项（ConfigMap） | 应用 | 应用详情「配置与密钥」 | 按作用域注入 env，或按目录挂成文件 |
| 密钥（Secret） | 应用 | 同上，勾选「作为密钥下发」 | `secretKeyRef`，或 `secret` 卷挂载 |
| 环境变量覆盖 | 工作负载 | 工作负载「配置与存储」 | 同名覆盖应用级取值，只作用于本负载 |
| 存储卷（PVC / emptyDir） | 工作负载 | 工作负载「配置与存储」 | 生成 `volumes` + `volumeMounts` |

密钥统一在应用级维护，是为了轮换时只改一处；工作负载只放非敏感变量。

### 两种挂载方式

- **环境变量**：注入容器 `env`，适合开关、超时、端点这类短值。Key 限大写字母、数字与下划线。
- **文件挂载**：同目录下的配置项合并成一个卷挂到容器里，Key 就是文件名（如 `application.yaml`），适合整份配置文件。挂载目录需以 `/` 开头。

### 存储

- **持久卷**：声明容量（`20Gi`）、存储类（`standard-ssd` / `ceph-rbd` / `local-path`）与访问模式，PVC 名为「负载名-卷名」。StatefulSet 走 `volumeClaimTemplates` 按副本独立申请，Deployment 走 `persistentVolumeClaim` 共享同名 PVC。
- **临时卷**：`emptyDir` + `sizeLimit`，随 Pod 重建清空，适合缓存与临时文件。
- **配置卷 / 密钥卷**：由文件挂载方式自动派生，只读，改配置即改文件内容，无需动负载。

### 界面

- 工作负载新增「配置与存储」页签：环境变量表区分「应用配置」与「工作负载」来源、密钥默认遮罩、同名覆盖有提示；存储卷表列出容量、存储类、访问模式与挂载路径，可增删（删除持久卷会提示 PVC 保留、数据不会自动清除）。
- 改动直接反映到 YAML：`env`、`volumeMounts`、`volumes`、`volumeClaimTemplates` 都由模型生成，不再有第二份硬编码。
- 运维中心新增「存储」页：按存储类汇总 PVC 数量与申请容量，搜索后可点任意 PVC 跳回对应工作负载的「配置与存储」页签。
- 应用「配置与密钥」页补了「挂载方式」「使用方（工作负载数）」两列，多行值只显示首行、完整内容在 tooltip 里。

流水线、发布记录与组件版本一并写入 `localStorage`，刷新后保留。

## 流量规则

`#/mesh/traffic` 把虚拟服务与目标规则做成可编辑的实体，不再是只读表格：

- **规则列表**：规则名 + 类型 chip、匹配条件、动作摘要、状态；支持关键字搜索与「虚拟服务 / 目标规则」筛选，行内可直接启停与删除。
- **新建 / 编辑**：匹配方式（所有请求 / 请求头 / 路径前缀 / 比例采样）与动作类型（权重路由、流量镜像、超时重试、熔断、异常点驱逐）切换时表单局部重绘，只展示当前动作需要的字段。
- **校验**：权重合计必须为 100、镜像目标不能是自身（否则回环）、路径前缀需以 `/` 开头、规则名全局唯一。
- **灰度权重卡**：读当前生效的权重规则，改完权重立刻反映到进度条；切换规则状态后卡片同步提示「规则已停用，权重不生效」。

## 边缘节点纳管

`#/edge/nodes` 与 `#/edge/nodes/<节点名>`：

- **添加节点**：登记设备（名称 / 类型 / 位置 / 归属集群 / 标签）后生成接入令牌，弹窗给出 `curl ... | sh` 接入命令，可一键复制；新节点以「待激活」进入列表。
- **节点详情**：CPU / 内存 / 磁盘水位、本节点工作负载（按节点标签调度，可跳到工作负载详情）、端设备列表、节点事件（心跳延迟、CPU 饱和、镜像预热、增量同步）。
- **容量曲线**：CPU、内存、回源延迟三条曲线，悬停有读数与相对时间；离线或待激活节点不伪造曲线，而是给出对应空态。
- **运维动作**：立即同步、封锁 / 解除调度、模拟上线（待激活节点）、移除节点（连带把端设备置为「未绑定」并提示重新调度）。

## 应用分发

`#/edge/distribute` 支持新建分发任务：选边缘工作负载、目标范围（全部在线节点 / 按城市 / 单节点）、策略与执行窗口；创建后任务按节点推进进度（约 8 秒到 100%），行点开是逐节点进度与「重新分发失败节点」。

## 集群接入

`#/ops/clusters` 与 `#/ops/clusters/<集群名>`：

- **接入集群**：填写名称、接入方式、区域、版本、API Server 与节点数，生成 `kubectl apply` 接入清单；新集群以「接入中」进入列表，不显示伪造的容量曲线。
- **完成校验**：点击后开始采集容量，状态变为「健康」。
- **集群详情**：节点 / Pod / CPU / 内存四项容量、CPU 与内存曲线、节点列表（control-plane 与 worker 区分）、集群信息（API Server、CNI、命名空间、承载工作负载）、承载的应用与集群事件。
- **维护与移除**：维护模式停止调度新实例但保留存量；移除只卸载 Agent，不删除目标集群内的业务负载。

## 环境与角色

- **新建环境**：名称 + 编码（唯一，小写开头）+ 绑定集群 + 变更策略（严格 / 标准 / 宽松），创建后进入环境列表。
- **新建角色**：角色名 + 数据范围（全部 / 按环境 / 按应用 / 仅本人）+ 操作权限（查看、发布与回滚、扩缩容、配置、成员、模块开关），「查看」是其它权限的前提。

## 链路追踪

Service Mesh 下的独立页面（`#/mesh/tracing`），把「谁调用了谁」的拓扑下钻到「这一次调用慢在哪一段」：

- **Trace 列表**：按状态（正常 / 慢调用 / 错误 / 超时）着色，每行带耗时对比条；支持 TraceID、接口、服务关键字搜索，按服务与状态筛选。
- **瀑布图**：8 条样例链路（含 3s 超时、支付渠道 502、边缘同步慢查询），Span 按父子层级缩进，时间轴按 25% 刻度对齐；点击任意 Span 高亮并同步右侧详情。
- **Span 详情**：耗时、起始偏移、链路占比、所在 Pod，以及 `http.status_code` / `db.statement` / `messaging.destination` 等标签与事件时间线（重试、TLS 握手、熔断探测）。
- **耗时分布**：按服务统计自身耗时（总时长减去子调用，已剔除嵌套重复计算），一眼看出哪一跳是瓶颈。
- **联动**：服务治理表格行、服务拓扑节点点击后跳到按该服务过滤的链路列表。

## 检索与列表操作

- **顶栏全局搜索**：按 `F` 聚焦，输入即匹配应用 / 组件 / 工作负载三层的名称，回车跳第一条，点击任意结果直达（组件会选中该组件）。
- **页面内检索**：应用列表（名称 / 业务域 / 负责人 / 描述）、流水线（名称 / 应用 / 组件 / 分支）、制品仓库、服务治理、边缘节点、端设备都支持关键字过滤。
- **状态筛选**：流水线（运行中 / 失败）、制品（amd64 / arm64）、服务治理（异常）、边缘节点（在线 / 离线）、端设备（按类型）的胶囊按钮已接上数据。
- **导出**：工作负载列表可导出 CSV（UTF-8 BOM，Excel 直接打开不乱码），字段含应用、组件、副本、调度位置与资源。

## 访问入口与依赖

- **新增入口**：应用详情「访问入口」或全局页均可新增，支持「域名」与「网关路径」两种形态，选择后端组件与端口、TLS、认证；域名做格式校验，路径做前缀校验，重复地址会被拦下。
- **启停与删除**：每条入口可停用 / 启用、删除，操作都会写入应用事件流。
- **编辑依赖**：组件拓扑页「编辑依赖」可增删组件间依赖（同步 / 异步），拓扑连线与组件卡片上的上下游标签会同步更新。

## 删除的级联范围

- 删除**应用**：连带组件、工作负载、访问入口、依赖声明、配置项、绑定流水线与发布记录一并清理。
- 删除**组件**：连带工作负载、绑定到该组件的流水线、它的发布记录、组件作用域配置，以及指向它的依赖边；应用下的流水线列表同步收缩。

## 打开方式

双击 `index.html`，或：

```bash
python -m http.server 8080
```

然后访问 http://localhost:8080

## 建议体验路径

1. 应用列表 → 新建应用：走完三步向导，创建后直接落到新应用的资源树
2. 应用详情 → 扩缩容：调整副本数，观察表格与事件流同步
3. 平台管理 → 模块管理：关闭 Service Mesh，观察应用详情页签与表格列的变化
4. 应用列表 → 智慧零售中台：左侧资源树逐层下钻三层模型
5. 应用详情 → 组件拓扑：查看自动布局的组件依赖图
6. 流水线 → order-service · 主干发布：8 阶段流程与实时日志
7. Service Mesh → 链路追踪：点开那条 1.42s 的慢链路，看支付渠道出口如何吃掉 79% 耗时
8. 工作负载 → order-service-api：切到「日志」看流式追加，再到「YAML」打开对比，看线上漂移
9. Service Mesh → 流量规则：新建一条权重路由，改权重后看右侧灰度卡同步变化
10. 云边端协同 → 边缘节点 → edge-hz-009：看告警节点的容量曲线与节点事件，再试「封锁调度」
11. 运维中心 → 集群管理 → 接入集群：走完接入 → 校验，观察容量曲线从空态变为实时数据
12. 工作负载 → order-service-api → 配置与存储：新增一个变量与一个持久卷，切到 YAML 看 env 与 volumes 同步变化
13. 运维中心 → 存储：按存储类看 PVC 汇总，点任意一行回到该负载的配置与存储页签
